# 데이터카드 만들기 (`/deal-card-image`)

`$ARGUMENTS` 를 해석해 **deal-locator MCP 의 `deal_card_create`** 를 호출한다.
조회부터 PNG 렌더까지 한 번에 이뤄지는 **유일한 쓰기 도구**다.

## 1) 인자 해석

- **주소** = `address` (`구 동 번지`).
- **파일 경로처럼 보이는 토큰**(`/`·`~` 로 시작하거나 `.jpg`·`.png` 로 끝남) = `photo`.
- **`N개월`** = `months`. 없으면 12개월.
- `eyebrow` 는 사용자가 문구를 명시할 때만 넘긴다.

## 2) 답변 규칙 (반드시 지킬 것)

1. **`PHOTO_MISSING` 은 실패가 아니라 사람의 결정을 기다리는 상태다.**
   **재시도하지 마라.** 카드는 건물 사진 위에 수치를 얹는 형태라, 사진이 없으면
   회색 판이 나가고 결국 다시 만들게 된다. 사용자에게 **사진 경로를 물어본다.**
   사진 없이 진행하겠다고 사용자가 명시하면 그때만 `allow_no_photo=true` 로 재호출한다.

2. **`LOW_CONFIDENCE` 도 실패가 아니다.** 매칭이 약한 상태로 이미지를 만들지 말지는
   사용자가 정할 문제다. **재시도하지 마라.** 무엇이 약한지(신뢰도·caveat) 전하고
   **`/match-explain` 으로 근거를 확인하도록 권한 뒤**, 사용자 판단을 기다린다.
   사용자가 그래도 발행하겠다고 **명시하면 그때만 `allow_estimated=true` 로
   재호출**한다(카드에는 신뢰도 배지가 함께 찍힌다). 추정매칭 카드는 동일 스펙 옆
   건물일 수 있으니, 고객에게 전달할 때 그 사실을 함께 알리도록 안내한다.

3. **eyebrow 에 단정 표현을 넣지 마라.** '최고가'·'최저가'·'역대급' 금지.
   이 도구의 조회 범위(서울 상업업무용·통건물·기간 한정) 안의 순위일 뿐인데
   이미지에 박히면 근거 없는 단정이 된다. 기본값(`<구> 실거래 · YYYY.MM`)이 안전하다.

4. **신뢰도 배지는 카드에 찍힌다.** 이미지가 손을 떠나면 대화로 고지할 수 없어서다.
   지우거나 가려달라는 요청은 받지 않는다 — 그 요청이 오면 이유를 설명한다.

5. **홍보 문구를 만들어 넣지 않는다.** 카드에 들어가는 값은 전부 실측값이다.

6. **만든 뒤 저장 경로를 그대로 알려준다.** 기본 `~/deal-locator-cards/<날짜>/`.

7. 최초 1회 `playwright install chromium` 이 필요하다. 관련 오류가 나면 이 명령을
   안내한다.

## 3) 출력 형태

성공하면:

```
카드를 만들었습니다 — ○○구 ○○동 123-4  [정확매칭]
저장: ~/deal-locator-cards/2026-07-24/구로구_구로동_1128-1.png

카드에 들어간 값: 매매가 115억 · 대지 52.9평 · 연면적 106.2평
                 평단가 1억 3,707만원/평 · 제2종일반주거 · 2002년 준공
```

- 신뢰도가 `추정매칭` 이하면 **고객 제시 전 `/match-explain` 확인**을 권한다.
- 게이트(`PHOTO_MISSING`·`LOW_CONFIDENCE`)면 **무엇이 필요한지 한 줄로 묻고 멈춘다.**
  임의로 진행하지 않는다.
