# 매칭 근거 확인 (`/match-explain`)

`$ARGUMENTS` 를 해석해 **deal-locator MCP 의 `match_explain`** 을 호출하고,
표제부 앵커값과 거래행값의 대조를 사용자가 스스로 판단할 수 있게 펼쳐 보인다.

**이 스킬의 목적은 설득이 아니라 검증이다.** 매칭이 약하면 약하다고 말하는 게 성공이다.

## 1) 인자 해석

- **주소** = `address` (`구 동 번지`).
- **`N개월`** = `months`. 없으면 12개월.

## 2) 답변 규칙 (반드시 지킬 것)

1. **`comparison` 을 그대로 펼친다.** 표제부 앵커(건축물대장) 대 거래행(실거래)의
   항목별 대조 — 연면적·대지면적·건축년도 — 를 `delta`·`equal` 과 함께 보인다.
   요약만 하고 숫자를 감추지 마라. **사용자가 직접 보고 판단할 수 있어야 한다.**

2. **발화 단계(`stage`)를 그대로 설명한다.** 어떤 단계로 매칭됐는지가 신뢰도의 근거다.
   - `지번매칭(비마스킹)` — 지번이 애초에 가려지지 않았다. 가장 강하다.
   - `1단계: 정확매칭` — 연면적·대지·건축년도가 모두 일치.
   - `2단계: 건축년도+연면적` — 대지 정보 없이 두 값만 일치.
   - `3단계: 오차범위 ±10%` — 근사 일치. **가장 약하다.**

3. **약한 매칭을 변호하지 마라.** 3단계나 `추정매칭`이면
   **"같은 스펙의 인접 건물일 수 있다"**를 분명히 말한다. 사용자가 "확실하냐"고
   물어 이 스킬을 부른 것이니, 확실하지 않으면 확실하지 않다고 답하는 게 정답이다.

4. **필지세트(`_필지세트`)가 여럿이면 합필 건물**이다. 대표지번 외 부속지번이
   있으면 나열한다 — 왜 이 지번으로 잡혔는지 이해하는 데 필요하다.

5. **고객 제시용이면 원문 확인을 안내한다.** 이 결과는 참고자료이지
   중개대상물 확인·설명서가 아니다. 실거래가 공개시스템·건축물대장 원문을
   직접 확인하도록 반드시 안내한다.

6. `status` 가 `OK` 가 아니면 사유를 그대로 전하고 추측하지 않는다.

## 3) 출력 형태

```
○○구 ○○동 123-4 — 2026-06-12 거래 매칭 근거
판정: 정확매칭 (1단계)

항목       표제부(앵커)    거래행(실거래)   차이
연면적       351.0㎡         351.0㎡        0     ✅
대지면적     175.0㎡         175.0㎡        0     ✅
건축년도       2002            2002         0     ✅

필지구성: 단일 필지
```

- 판정이 `추정매칭` 이하면 표 아래 **한 줄 경고**를 붙인다.
- 마지막에 도구가 준 `source` 한 줄을 유지한다.
