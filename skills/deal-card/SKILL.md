# 지번 실거래 조회 (`/deal-card`)

`$ARGUMENTS` 를 해석해 **deal-locator MCP 의 `deal_card_search`** 를 호출하고,
결과를 중개 실무 규칙에 맞게 정리해 답한다.

## 1) 인자 해석

- **주소** = `address`. `구 동 번지`(예: `구로구 구로동 1128-1`)가 가장 정확하다.
  구가 없으면(`구로동 1128-1`) 엔진이 역추적하니 그대로 넘기고, 결과의 구를 확인해
  사용자에게 알린다.
- **`N개월`** = `months`. 없으면 기본 12개월.
- 주소가 모호하거나 파싱이 실패하면 **`/resolve-address` 로 먼저 확인**한다.

## 2) 답변 규칙 (반드시 지킬 것)

1. **`status` 가 `OK` 일 때만 `latest` 에 실측값이 있다.** 그 외에는 사유를 그대로
   전하고 수치를 추측·보간하지 않는다. `NOT_FOUND` 는 "데이터가 없다"는 뜻이지
   "거래가 없었다"는 확정이 아니다 — 기간을 늘려 재조회할 수 있음을 안내한다.

2. **매칭 신뢰도를 반드시 함께 말한다.** 이 도구의 핵심은 마스킹된 지번을 표제부로
   역추적한 것이라, 신뢰도가 곧 답의 품질이다.
   - `확정`·`정확매칭` — 그대로 전한다.
   - `추정매칭` — **"동일 스펙의 인접 건물일 가능성이 있다"**를 반드시 붙인다.
     사용자가 고객에게 제시할 상황이면 `/match-explain` 으로 근거를 확인시킨다.
   - `인접후보` — 질의한 지번이 아니라 같은 본번의 다른 건물이다. 이 사실을 먼저 말한다.

3. **금액은 반올림**해 적는다(절사 금지). 평단가는 도구가 준 `만원/평` 을 그대로 쓰고,
   1억원/평을 넘으면 `1억 5,067만원/평` 처럼 억 단위를 앞에 붙인다.

4. **통건물만 취급한다.** 이 MCP 는 집합(구분상가)을 제외한다. 상가 한 칸을 물으면
   범위 밖임을 밝히고 답을 지어내지 않는다.

5. **계산·인용은 `structuredContent` 로 한다.** 텍스트를 파싱해 숫자를 만들지 않는다.

6. **첫 조회는 수십 초 걸릴 수 있다**(표제부·실거래 API). 오래 걸려도 재시도하지 말고
   기다린다. 같은 구를 다시 보면 캐시로 즉시 응답한다.

## 3) 출력 형태

```
○○구 ○○동 123-4  [정확매칭]

매매가     115억원  (2026-06-12)
대지 평단가 1억 3,707만원/평   ·  연면적 평단가 X,XXX만원/평
토지/연면적 52.9평 / 106.2평
용도지역   제2종일반주거   ·  준공 2002년
매도/매수  개인 → 법인
도로명     서울특별시 ○○구 ○○로 12
```

- 신뢰도가 `추정매칭` 이하면 표 바로 아래에 **한 줄 경고**를 붙인다.
- 마지막에 도구가 준 `source` 한 줄을 유지한다.
- 사용자가 고객 제시용이라고 하면 **"이 결과는 참고자료이지 중개대상물 확인·설명서가
  아니다 — 원문(실거래가 공개시스템·건축물대장)을 직접 확인하라"**를 덧붙인다.
